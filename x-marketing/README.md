## 1. 最初の1回だけやること

### ① リポジトリを非公開にする
GitHub のリポジトリ画面 → Settings → General → 一番下の「Change repository visibility」→ **Private**。
（個人データは Git に入らない設定にしてありますが、念のため）

### ② 自分のPCにコピー（clone）する
```bash
git clone https://github.com/tu23hin-blip/-.git x-repo
cd x-repo/x-marketing
```
Python 3.8 以上が必要です（Mac は最初から入っていることが多いです。Windows は Microsoft Store の「Python 3」を入れると `python3` が使えます）。

### ③ 初期設定をする
```bash
bash scripts/init.sh
```
`templates/` から `inbox/`・`knowledge/`・`data/` が作られます。何度実行しても、すでにあるファイルは上書きしません。

### ④ knowledge/ を記入する（ここが一番大事）
| ファイル | 書くこと | 優先度 |
|---|---|---|
| knowledge/profile.md | アカウント設定（@rooney102323・運用モード・発信ジャンルは記入済み）、経歴・実績・ストーリー（**事実だけ**） | ★★★ |
| knowledge/voice.md | 口調（一人称・語尾・絵文字）、良い例・悪い例 | ★★★ |
| knowledge/ng-words.md | 使わない言葉（最初から入っているものは消さない） | ★★ |
| knowledge/products.md | 収益化モードになるまで記入不要 | － |

「※例：削除して上書きしてください」とついた記入例は、消して自分の内容に書き換えてください（記入例は事実として使われません）。

### ⑤ Claude Code を起動して「信頼」する
```bash
cd x-marketing     # ← 必ずこのフォルダに移動してから起動する
claude
```
- **必ず `cd x-marketing` してから `claude` を起動してください。** リポジトリの一番上（x-repo）で起動すると、このチームの設定（.claude/ と CLAUDE.md）が読み込まれません。
- 初めて起動すると「このフォルダを信頼しますか？」と聞かれるので、**信頼する（Yes）** を選んでください。これをしないと、許可設定（.claude/settings.json）が使われず、毎回確認が出ます。定時実行も正しく動きません。

## 2. 毎朝やること（5〜10分）

1. **材料を inbox/ に貼る**（書き方は「5. inbox/ に何をどう貼ればいいか」）
   - inbox/buzz-posts.md：伸びている投稿（前日の分は消して、新しく貼る）
   - inbox/accounts.md：交流したい相手と、その人の直近の投稿
   - inbox/mentions.md：自分に来たリプ・引用（あれば）
   - inbox/instructions.md：今日の指示（なくてもOK）
2. **Claude Code で `/x-morning` を実行**（10〜20分ほど待ちます）
3. 画面に出る「今日の結論」と「社長の判断が必要なこと」を読む
4. **dashboard/index.html を開く**（ダブルクリック。ブラウザにブックマークしておくと便利）
5. 「承認キュー」で ★おすすめ を確認 → **「Xで開く」** → X の画面で内容を確かめて、**自分で投稿ボタンを押す**
6. 投稿したら **「投稿済み」にチェック**（投稿URLを貼っておくと、あとの分析が正確になります）
7. 最後に **「/x-log 用にまとめてコピー」** → Claude Code に貼り付けて送信 → 記録完了
8. 「いいね回り」のリストを見ながら、朝・昼・夜に分けて手動でいいね（チェックすると進捗 〇/40 が進みます）

## 3. ダッシュボードの見方

`dashboard/index.html` をダブルクリックすると、ブラウザで開きます（サーバー不要・オフラインでも表示できます）。
ブックマークしておくと毎朝すぐ開けます。データは `/x-morning`・`/x-log`・`/x-weekly` のたびに自動で作り直されます（手動なら `/x-dashboard`）。

| タブ | わかること |
|---|---|
| 今日 | テーマ方針／社長の判断が必要なこと／チーム稼働ボード（カードを押すと各チームの提出物）／承認キュー（コピー・Xで開く・投稿済み）／いいね回り（進捗 〇/40）／社長にお願いしたい作業（inbox/ が古いと警告） |
| 成果 | フォロワー数・7日間の増減・インプレッション・エンゲージメント率・プロフィールクリック・フォロー率（前週比つき）／フォロワー推移／型別・時間帯別の成績／伸びた投稿TOP5／投稿数の推移 |
| 履歴 | 日付を選んで、その日のチームの状況と案を振り返る／採用率（案のうち実際に投稿した割合）の推移 |
| 学び | knowledge/learnings.md の最新10件（取り消し線の学びはグレー）／最新の週次レビューの「来週の提案」 |

- チーム稼働ボードの色：緑＝提出済み／黄＝差し戻し後に修正済み／赤＝修正後もNG／オレンジ＝未提出／グレー＝今日は稼働なし
- 右上に生成日時と、テーマ（自動／ライト／ダーク）の切り替えがあります
- 「投稿済み」のチェックは、そのブラウザの中だけに保存されます（別のブラウザやスマホには引き継がれません）。/x-log で記録したものは全体に反映されます

「Xで開く」ボタンの動き：

| 種類 | 開くもの |
|---|---|
| 勝負ポスト・通常ポスト・スレッドの1本目・告知・固定ポスト | 本文が入った投稿画面（投稿ボタンを押すのは社長） |
| リプ・返信 | 相手の投稿（本文は自動でコピーされるので、返信欄に貼る） |
| 引用 | 相手の投稿（本文をコピー → 「リポスト → 引用」で貼る）。URL不明なら本文入りの投稿画面 |
| スレッドの2本目以降 | 開きません（前の投稿への返信として、コピーした本文を貼る） |
| プロフィール文 | X のプロフィール編集画面（本文をコピー） |
| いいね | 相手のプロフィール |

## 7. 運用モード（今は「フォロワー増加」）

`knowledge/profile.md` の「アカウント設定」にある `運用モード:` で、チーム全体の動きが切り替わります。

| | フォロワー増加（今） | 収益化 |
|---|---|---|
| 目的 | フォロワーを増やすことだけ | フォロワー増加＋LINE登録＋商品販売 |
| 投稿 | LINE・商品・販売への言及はゼロ。週1〜2回まで「フォローするメリット」が伝わる投稿 | 週1回まで商品・LINEに触れてよい |
| 記事の最後 | フォロー・プロフィールへの誘導 | LINE特典への誘導 |
| マネタイズ | /x-monetize のときだけ、プロフィール文・固定ポスト・ヘッダーの改善案 | LINE導線・商品企画・導線チェック |
| ダッシュボード | 「フォロー率」を表示 | 「LINE登録数」を表示 |

**収益化モードへの切り替え方（3ステップ）**
1. `knowledge/products.md` に LINE登録URL・特典・商品を書く
2. `knowledge/profile.md` の `運用モード: フォロワー増加` を `運用モード: 収益化` に書き換える
3. 次の `/x-morning` から LINE・販売の導線が有効になる（ダッシュボードは `/x-dashboard` ですぐ切り替わる）

## 8. 毎朝6:30に自動で動かす（任意）

`scripts/morning.sh` は、このフォルダで `claude -p "/x-morning auto" --permission-mode dontAsk` を実行します。
- 定時実行では社長に確認できないので、**今日の logs/ にすでに成果物があれば、何もせずに終了**します
- 許可されていない操作は自動で断られます（安全側に倒れます）
- 実行の記録は `logs/_cron/日付.log` に残ります
- 先に「1. ⑤」の「信頼する」を済ませておいてください（済んでいないと、ログに ⚠️ が出ます）

### Mac / Linux（cron）
```bash
crontab -e
```
次の1行を追加（パスは自分の場所に合わせる）：
```
30 6 * * * /bin/bash "$HOME/x-repo/x-marketing/scripts/morning.sh"
```
- PC がスリープ中だと動きません
- Mac で動かないときは「システム設定 → プライバシーとセキュリティ → フルディスクアクセス」に `/usr/sbin/cron` を追加してください
- PC の時刻が日本時間になっている前提です

### Windows（タスクスケジューラ）
1. 「タスクスケジューラ」→「基本タスクの作成」→ 名前「X Morning」
2. トリガー：毎日 6:30
3. 操作：プログラムの開始
   - プログラム：`C:\Program Files\Git\bin\bash.exe`
   - 引数：`-lc "cd /c/Users/あなたの名前/x-repo/x-marketing && bash scripts/morning.sh"`

### ログインのエラーで止まるとき
ターミナルで `claude setup-token` を実行してトークンを作り、**リポジトリの外**のファイル `~/.x-marketing.env` に次の1行を書いてください（Git には入りません）。
```bash
export CLAUDE_CODE_OAUTH_TOKEN=（作ったトークン）
```
`claude` コマンドが見つからないと言われたら、同じファイルに `export CLAUDE_BIN=/claude/の/フルパス` を書きます（`which claude` で調べられます）。

## 9. 困ったとき

| こんなとき | こうする |
|---|---|
| 案の口調がイマイチ | knowledge/voice.md に良い例・悪い例を足す |
| 伸びない・方向がズレる | knowledge/learnings.md の学びを見直す／inbox/instructions.md でテーマを指定する |
| 実績が使われない | knowledge/profile.md に事実として書く（書いていない数字は使われません） |
| 同じネタばかり | knowledge/idea-bank.md にネタを足す |
| 毎回「許可しますか？」と聞かれる | `cd x-marketing` してから起動しているか、「信頼する」を選んだかを確認 |
| /x-morning が見つからない | `cd x-marketing` してから `claude` を起動し直す |
| ダッシュボードが古い | `/x-dashboard` |
| 「投稿済み」のチェックが消えた | 別のブラウザで開いた・履歴を消した可能性。/x-log で記録したものは消えません |
| JSON のエラーと言われた | /x-morning が自動で直します。手動で確かめるなら `python3 scripts/build_dashboard.py --check 2026-09-26` |
| 足りないデータを知りたい | `/x-status` |
| `python3` が見つからない（Windows） | Microsoft Store の「Python 3」を入れる |

**個人データについて**：`inbox/`・`knowledge/`・`data/`・`logs/`・`dashboard/index.html` は `.gitignore` で Git に入らないようにしてあります。バックアップしたいときは、フォルダごと別の場所にコピーしてください。

## 11. 安全のための約束
- X への投稿・いいね・リプ・フォローは自動で行いません。X API やブラウザ自動操作のコードも作りません
- inbox/ と knowledge/ にない数字・実績・URL は作りません（「不明」と書きます）
- 文字数は目視ではなく `scripts/count_chars.py` で機械的に検査します
- `curl`・`wget` などの外部送信コマンドは `.claude/settings.json` で禁止しています（Web を読むのは WebSearch / WebFetch だけ）
