# AI会社 — 全体ルール

このリポジトリは「事業部ごとのAIが裏で作業し、人間が画面で動きと成果を確認・承認する」ための仕組みです。
Claude（および各事業部のSkill／サブエージェント）は、どの作業でも以下のルールを必ず守ってください。

## 1. 公開・投稿・送信・購入は絶対に自動で行わない
- X・note・動画サービス・自サイトなどへの **公開／投稿／送信／購入／課金／フォロー等の外部アクション** は一切実行しない。
- 成果物は必ず `outputs/` に **下書き** として保存し、DBの `outputs.approval = 'pending'` で止める。
- 公開するかどうかは人間が画面の「承認待ち」から判断し、人間が手動で投稿する。
- 外部サービスのAPIキーがあっても、書き込み系のAPIは呼ばない。

## 2. 作業の開始・終了・失敗は必ず events に記録する
- タスク開始時：`start_task`（events に `start`）
- 途中経過：`log_event`（`progress`）
- 成果物保存：`save_output`（approval=pending）
- 正常終了：`finish_task`（`finish`）
- 失敗：`fail_task`（`fail`、エラー内容を `tasks.error` に残す）
- 記録なしで作業を終えてはいけない。例外で落ちる場合も `fail_task` を呼ぶ。

## 3. 数字を捏造しない
- 売上・インプレッション・フォロワー数などは、実データ（CSV取り込み・人間の入力）にあるものだけを使う。
- 不明な数字は **0 ではなく null**。推測値を事実として書かない。
- 投稿文や記事でも、根拠のない実績・収益額・人数を書かない。
- 数字が足りないときは「何を入力すれば分析できるか」を明記する。

## 4. 各媒体の規約とステマ規制を守る
- X・note・YouTube・TikTok などの各利用規約、および景品表示法（ステルスマーケティング規制）を守る。
- アフィリエイトリンク・PRを含む投稿には **「PR」「広告」等の表記** を入れる。
- AIが生成した成果物には **AI生成であることの明記**（例：「※AIを活用して作成」）を入れる。
- 誇大表現・断定的な収益の約束（例：「誰でも月50万」）は禁止。
- 実在人物の顔・声・名前を無断で使わない。著作物を無断転載しない。

## 5. 判断に迷ったら knowledge/ を参照する
- テーマ、口調（`knowledge/my-voice.md`）、過去の週次レポート（`knowledge/reports/`）、事業方針は `knowledge/` にある。
- それでも決められない場合は、勝手に決めずに成果物の中に「確認したい点」として書き、承認待ちに出す。

## 6. 秘密情報の扱い
- APIキー・トークン類は **`.env` のみ** に置く（`.env.example` には値を書かない）。
- `.env` と `outputs/` は `.gitignore` 済み。コミットしない。
- ログ・events・成果物にキーを出力しない。

## 7. 設定を勝手に変えない
- `divisions.weekly_goal` や事業部の状態など、方針に関わる値は直接書き換えず、変更案を承認待ちに出す。

## 構成メモ
- `knowledge/` … 判断材料（テーマ、口調、レポート）
- `.claude/skills/<事業部>/SKILL.md` … 事業部ごとの作業手順
- `.claude/agents/` … サブエージェント（分析担当など）
- `engine/divisions/<事業部>/` … Skill を `claude -p` で呼び、DBに記録する実行コード
- `engine/scheduler/` … 定時実行
- `engine/db/` … SQLite と記録用ライブラリ
- `outputs/` … 下書き成果物（git管理外）
- `web/` … 経営ダッシュボード／事業部ビュー（Next.js）

事業部を1つ追加する ＝ `.claude/skills/<slug>/` と `engine/divisions/<slug>/` を1つずつ追加する。
