# AI編集部 制作パイプライン（使い方）

コマンドを1回実行すると、ネタ選びから X 投稿の下書きまでを AI が自動で作ります。
**人間がやるのは「完成品を確認して、note と X に投稿する」ことだけ**です。

```
ジャンル探索 → ネタ選定 → リサーチ → 構成 → 本文 → 図解 → アイキャッチ → 校閲 → X投稿生成
 (週1回)                                               ↑不合格なら最大2回書き直し
```

---

## 1. はじめに（最初の1回だけ）

1. [Node.js](https://nodejs.org/ja)（20.12 以上）をインストールする
2. このフォルダでターミナルを開き、次を順に実行する
   ```
   npm install
   npx playwright install chromium
   ```
   2行目は、図解を画像にするためのブラウザを入れるコマンドです。
3. `.env.example` をコピーして `.env` という名前にし、`ANTHROPIC_API_KEY=` の後ろに Claude の API キーを書く
4. まずはお試し（API を使わないので0円です）
   ```
   npm run demo
   npm start
   ```
   ブラウザでダッシュボードが開いたら、左のメニューの「**投稿待ち**」を押します。デモ用の完成品が1本並んでいれば準備完了です。

## 2. 毎日の使い方

### 記事を1本作る

```
npm run produce -- --genre ai-note-automation   ← ジャンルを指定する
npm run produce -- --auto                       ← ジャンルもネタも編集長に任せる
```

数分で `output/<日付>_<ジャンルID>-<英数字>/` に完成品ができます。

| ファイル | 中身 |
| --- | --- |
| `note_body.html` | noteのエディタにそのまま貼れる本文（見出し・太字・箇条書き） |
| `note_body.md` | 同じ内容の Markdown |
| `images/01.png` など | 図解（本文の [図1] と番号が対応）1280×720 |
| `eyecatch.png` | アイキャッチ 1280×670 |
| `meta.json` | タイトル、価格、ハッシュタグ、有料ラインの位置、マガジン、校閲結果、費用 |
| `x_posts.json` / `x_posts.md` | X投稿7本と、推奨の投稿日時 |
| `publish_checklist.md` | 投稿手順（画像を入れる位置、有料ラインを引く位置、価格） |
| `work/` | 途中経過（AIの出力と実行ログ）。うまくいかなかったときの確認用 |

### ダッシュボードで投稿する

`npm start` で開くダッシュボードの「投稿待ち」に、完成品が並びます。

1. **本文をコピー（リッチテキスト）** を押して、noteのエディタに貼り付ける
2. 黄色の【図N】の行に画像を、赤の【ここに有料ラインを引く】の行に有料ラインを入れる（**画像を一括ダウンロード** で画像をまとめて保存できます）
3. 価格・アイキャッチ・ハッシュタグ・マガジンを設定して公開する（**投稿手順** に全部書いてあります）
4. 公開した note の URL を「投稿を記録する」に保存する
5. 「X投稿」を開き、1本ずつ **コピー** して X の予約投稿に入れる（誘導投稿の `[noteのURL]` は、保存した URL に自動で置き換わります）
6. 投稿したら XのポストのURL を入れて **投稿済みにする**

**赤く表示された「要確認」** は、校閲に2回書き直しても合格しなかった記事です。理由が表示されるので、直すか公開をやめるかを判断してください。

## 3. 週1回の作業

```
npm run analyze   ← 週次分析（先にダッシュボードで各記事の数字を記録しておく）
npm run scout     ← 新しいジャンルの探索（候補数は npm run scout -- --count 5）
```

- **analyze** は、勝ちパターン（`data/patterns.json`）を更新し、ジャンルを「続ける / active に上げる / 撤退（retired）」に振り分けます。レポートは `data/reports/` に出ます。検証期間（標準14日）が終わるまでは、昇格も撤退もしません。
- **scout** は、候補を `testing`（検証中）として `data/genres.json` に追加します。登録済みのジャンルは変えません。

## 4. 各工程とAI役

| # | 工程 | AI役（プロンプト） | Web検索 | 作り直しのルール |
| --- | --- | --- | --- | --- |
| 1 | ジャンル探索 | genreScout（第1章） | − | − |
| 2 | ネタ選定 | editorInChief（第2章） | − | AIの採点をシステムが計算し、70点以上で note化、50点以上は「Xでテスト」（`data/x_tests.json` に保存） |
| 3 | リサーチ | researcher（第3章） | ○ | − |
| 4 | 構成 | outliner（第4章） | − | − |
| 5 | 本文 | writer（第5章） | − | 校閲が不合格なら指摘を渡して書き直し（最大2回） |
| 6 | 図解の中身 | diagrammer（第6章） | − | 文字数・要素数の違反は1回だけ直させる |
| 7 | 図解の画像化 | システム（テンプレート） | − | 描けない図はAIにHTMLを書かせる → それも無理なら簡易図 |
| 8 | アイキャッチ | eyecatch（第7章） | − | 文字数の違反は1回だけ直させる |
| 9 | 校閲 | reviewer（第8章） | ○ | 合格 / 書き直し / 要確認 |
| 10 | X投稿7本 | xConverter（第9章） | − | 類似投稿・URL・文字数の違反は1回だけ作り直させる |
| 11 | 投稿日時 | xPlanner（第10章） | − | ルール違反ならシステムが割り当てる |
| 12 | 週次分析 | analyst（第11章） | − | − |

- どの役も JSON で答えます。読み取れなかったときは1回だけ出し直しを頼み、それでもだめなら止まります。
- 校閲の判定は、AIの判定と、プロンプトに書いた判定ルール（重要項目の不合格・不合格2つ以上・スコア70未満）の **厳しい方** を採ります。
- プロンプトは `docs/ai-editorial-prompts.md` にまとめてあります。編集したら `npm run prompts` で `prompts/` に反映してください。

## 5. 費用

- 実行の最初に、1本あたりの概算がログに出ます。概算は多めに見積もっています（実際の費用は `meta.json` と `work/run_log.txt` に記録されます）。
- `.env` の `COST_LIMIT_PER_RUN`（米ドル）を超えそうになったら、API を呼ぶ前に止まります。書き直しの途中で上限に近づいた場合は、書き直しをやめて「要確認」として仕上げます。
- 目安（多めの見積もり）：Claude Opus 5 で通常 約3.3ドル、書き直し2回で最大 約6.7ドル。Claude Sonnet 5 なら通常 約1.4ドルです。
- 安くしたいときは、`.env` で `LLM_MODEL=claude-sonnet-5` にするか、役ごとに `LLM_MODEL_X_CONVERTER=claude-sonnet-5` のように指定します。

## 6. 画像の作り方

画像生成AIは日本語の文字が崩れるので、**AIには中身（JSON）だけを決めさせ、文字はテンプレートとフォントで描きます**。

- 図解は7種類：flow（手順フロー）/ steps（番号付きステップ）/ compare（比較表）/ checklist / before_after / bar_chart（数値比較）/ matrix（2軸マトリクス）
- テンプレートは `templates/diagrams/`（HTML と CSS）。見本は `npm run render:samples` で `output/_samples/` に出ます
- フォントは Noto Sans JP を `templates/fonts/` に同梱しています（SIL Open Font License）
- 配色は `data/genres.json` の各ジャンルの `colors`（primary / secondary / accent）で変えられます
- アイキャッチは3種類の構図（中央に大きく / 左に文字・右にアイコン / ビフォーアフター）。`.env` の `IMAGE_API_PROVIDER=openai` を設定したときだけ、背景に生成画像を使います（文字はいつもテンプレートで描きます）

## 7. data/ のファイル

| ファイル | 役割 | 誰が書くか |
| --- | --- | --- |
| `genres.json` | ジャンル一覧（status: testing / active / retired、配色、文体、成功基準） | scout・analyze（手で直してもよい） |
| `patterns.json` | 勝ちパターン・X投稿の配分 | analyze |
| `operator.md` | 運営者の得意分野・経験（ジャンル探索で使う） | 人間 |
| `trends.md` | 気になるニュースのメモ（`.env` の `TREND_FEEDS` のRSSも読みます） | 人間 |
| `experiments/<ジャンルID>.md` | 実際にやってみた結果。記事の一次情報になる | 人間 |
| `x_tests.json` | 「Xでテスト」のネタ（初回の制作で自動で作られます）。反応の数字を `metrics` に書くと、次回の編集長が参考にする | 自動＋人間 |

## 8. やらないこと（安全のため）

- note への自動公開（公式の投稿APIがないため。ブラウザ操作による自動投稿もしません）
- X への承認なしの自動投稿、自動いいね、自動リプライ、自動フォロー（投稿は人間が確認して予約します）
- 複数のアカウントで同じ・似た内容を投稿すること（`needs_separate_account` のジャンルは、自動選択の対象から外しています）

## 9. うまくいかないとき

| 表示 | 対処 |
| --- | --- |
| `ANTHROPIC_API_KEY` が見つからない / キーが無効 | `.env` のキーを確認する |
| ブラウザを起動できませんでした | `npx playwright install chromium` を実行する |
| 費用の上限に達しそうなため停止しました | `.env` の `COST_LIMIT_PER_RUN` を上げるか、安いモデルにする |
| note化の基準を満たすネタがありませんでした | 別の日に実行するか、`--force` を付ける |
| 出力をJSONとして読み取れませんでした | もう一度実行する。続く場合は `work/` の内容を確認する |
| ダッシュボードに完成品が出ない | `npm start` で開いたダッシュボードか確認し、「再読み込み」を押す |
| スマホや別のPCから「投稿待ち」が見られない | 未公開の記事を守るため、標準ではこのPCからだけ見られます。`.env` に `DASHBOARD_ALLOW_REMOTE=1` を書くと許可できます（同じWi-Fiの人も見られるようになります） |
